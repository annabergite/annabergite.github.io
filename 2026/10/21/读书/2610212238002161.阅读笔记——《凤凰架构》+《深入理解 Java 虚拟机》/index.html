分布式系统开发文档-《凤凰架构》笔记

看了两本书，分别是《深入理解java虚拟机》和《凤凰架构》，分别讲述了JVM和分布式系统，对于系统开发非常有帮助。 希望这篇文章能对我有意义 本文主要解决2个问题

  • 学习了JVM，分布式系统怎么体现在开发者工作中
  • 学习了JVM，分布式系统怎么体现在简历中

《深入理解JVM虚拟机》知识点

学习JVM是为了更好的开发Java，当前的许多Java八股文就是源自于JVM虚拟机

JVM问题排查

如果JvisualVM接入Java，可能需要重构代码 不同的JVM排查工具

  • arthas 可以查看方法调用的Java行 查看线程信息 查看对应方法的入参和返回 导出火焰图，替代perf命令
  • MAT 可以查看堆内存信息分配
  • jprofiler 远程连接监控JVM，类似Prometheus,图形化监控堆、线程、类加载
  • JvisualVM 远程连接监控JVM，类似Prometheus,图形化监控堆、线程、类加载
  • Java命令 jcmd功能强大，可以直接替代其他Java命令 jps查看Java进程，也可以通过ps aux|grep java,ps ef |grep java 查看 jstat查看不同的GC的数量，GC的次数，GC原因，GC的对象大小 jmap导出堆转储文件 jinfo查看JVM信息参数，也可以用 java XX:+PrintFlagsFinal等命令可以替代 jstack查看线程状态（需要有Java线程模型的知识）对于Waiting或者Blocked可以查看下堆栈
  • Java自带启动参数 GC 日志分析，可以通过Gceasy查看，与jstat功能相似 崩溃自动导出Hprof，重要 Xmx,Xms等保持一致，避免出现 默认GC，内存小+吞吐量要求：不变Parallel，内存大：G1，内存小+响应时间要求：CMS -XX:+PrintCompilation 查看哪些方法被编译了，何时编译的 -XX:NativeMemoryTracking=detail jcmd VM.native_memory [summary|detail|baseline|diff]Native Memory Tracking (跟踪 JVM 自身内存使用)
  • NMT Native Memory Tracking (跟踪 JVM 自身内存使用)

《凤凰架构》知识点

实际上只知道凤凰架构对于开发并没有什么用处，真正需要知道的是对应的各个组件，我需要画大量时间学习这些组件才行。

其他Java 书籍的简短书评

  • 《Java性能优化权威指南》：屠龙术，实际上不会有人看
  • 《Java语言规范》：打发时间
  • 《领域驱动设计》：讲述云里雾里，只是讲了一个拆分微服务，规划微服务的方式，内容可以精巧到一个小册子上，章节间不具有很强的相关性，章节内的逻辑链条有时不清晰。
  • 《微服务架构设计模式》：比较好，推荐阅读，内容上可以包含《领域驱动设计》
  • 《从Paxos到zookeeper》：是《凤凰架构》中一致性算法的一部分补充（paxos的），zookeeper地方没怎么看，业务没用到
  • 《effective Java》：基础能力，常看常新，推荐经常看
  • 《Redis开发与运维》：推荐查看《凤凰架构》中的分布式缓存部分的细化
    可能最近这段时间我已经违背了阅读的初衷，是否花时间阅读，阅读多长时间，阅读哪些，阅读有没有用处，阅读产生的效果在我面试、工作和生活上面有没有用处，这些选择都要有效果，坚持这种方式真的压垮了我，我想我的方向是错误的 首先我知道了自己需要什么，不仅如此，强行的功利化看书和面试成功是错误的观念，现在要做的就是把阅读变成一个真正让人快乐的爱好，以及找到方法面试成功
